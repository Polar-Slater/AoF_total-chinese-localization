# 物品仓库布局修复

2026-11-17，用户报告物品仓库内容挤在中央，装备分类变成窄按钮，角色属性被截断。

## 原因与修复

物品仓库的内容区域固定为950×500像素，角色栏期望350×500像素，物品栏期望590×467像素。“财宝”标签使用18点粗体按钮字体，上下各有4像素边距。

安装中的原版 Noto Sans SC Regular 在游戏Java运行时中产生27像素行高，标签需要35像素，合计502像素。超出500像素后，GridBag布局退回最小尺寸，导致两栏同时缩窄。日志未显示对应加载异常；这是字体度量与固定布局不兼容，缺字检查无法发现。

新增 `prepare_ui_font.py`，从原始常规字重字体生成独立家族 AoF Han UI。将水平排版的行高参数设为1.0 em上升部与0.2 em下降部，仅用于 `BUTTONTEXT_FONT`。原始字形、字符映射、字宽和排版规则保持不变；正文、剧情、战斗文字仍用原字体。独立家族名还避免Java对同名字体复用度量缓存。

修复后18点粗体行高为22像素，标签占30像素，合计497像素；测试中的角色栏与物品栏均保持完整尺寸。未修改游戏程序、译文内容、存档或分辨率设置。

## 验证与部署

- `CheckInventoryLayout.java` 用独立Swing布局夹具检查固定尺寸组合，原字体复现溢出，修正字体在0、623和123456789金币文本下均通过。最小尺寸为夹具示例值，不声称重建了全部游戏控件。
- 对比原字体和修正字体，字形轮廓、全部cmap映射、字宽、GSUB及GPOS规则保持一致。字体序列化可能改变表的字节排列，不等于改变字符映射。
- 安装副本通过Java属性解码和四种字体样式的字符覆盖检查：6,678条运行时条目，1,446条英文回退。安装中的战役文件比当前仓库更新，因此保留原文件；这些数量不用于更新仓库翻译进度。
- 完整备份后，仅安装主消息文件的按钮字体配置、新字体文件及字体说明。SHA-256核对确认所有其他文件不变，包括原字体、战役译文和模组配置。
- OFL原许可文本保持不变，说明文件记录了派生字体与修改内容。字体二进制继续留在本地，不加入Git。

字体会被游戏缓存，须完全退出后重新启动。尚未获得修复后的游戏内画面确认；布局夹具通过不等于已实测完整界面。未上传Steam或推送GitHub。
